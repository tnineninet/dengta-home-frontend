# OpenAI Codex for Open Source 计划核验

核验日期：2026-08-10
资料范围：仅使用 OpenAI 官方页面与官方申请表。X 帖和视频只作为待核验线索，不作为事实来源。

## 结论

该计划真实存在，官方名称为 **Codex for Open Source**（条款称 **Codex for OSS Program**），官方申请表目前可打开并填写。

官方权益介绍包括：

- 6 个月 ChatGPT Pro（含 Codex）；
- 面向符合条件仓库的 Codex Security 有条件访问；
- 用于开源维护工作流的 API 额度。

但是，“只要有一个公开 GitHub 仓库并填表就能获得权益”并不准确。官方面向活跃开源项目的主要或核心维护者，审核会参考仓库使用情况、生态重要性、活跃维护证据、申请人的维护角色或权限，以及计划容量。提交申请不保证入选或获得任何特定权益。

X 帖所称“$1,200”不是 OpenAI 在该计划页面或条款中给出的官方金额。官方条款反而明确，计划权益没有现金价值；因此不应在 DengTa 宣传或申请材料中把它写成 OpenAI 保证提供的 $1,200 现金或等价额度。

## 官方入口

- 计划介绍：[Codex for Open Source](https://developers.openai.com/community/codex-for-oss)
- 官方申请：[Codex for Open Source application](https://openai.com/form/codex-for-oss/)
- 官方条款：[Codex for Open Source Program Terms](https://learn.chatgpt.com/docs/codex-for-oss-terms)
- OpenAI 组织 ID：[Organization settings](https://platform.openai.com/settings/organization/general)

## 当前资格与审核方式

官方页面和表单共同表明：

- 申请人应是活跃开源项目的主要维护者或核心维护者；
- GitHub 个人资料需要公开；
- 申请仓库需要公开；
- 项目应具有实质性使用量、广泛采用度，或能说明其对软件生态的重要性；
- 申请人需要提供持续维护工作的证据，例如 PR 审查、Issue 分类、发布管理等；
- 需要有效 ChatGPT 账户，并提交与该账户关联的邮箱；
- OpenAI 可以验证身份、仓库关系、维护者状态或仓库控制权；
- 申请不保证获选，权益的范围、持续时间和发放时点可能因申请人、仓库或用途而异；
- 不应在申请中提交机密信息。

官方没有公布最低 Star 数、最低下载量或“必须让朋友刷 Star”的规则。Stars、月下载量与生态重要性只是申请人可用来证明项目影响力的材料。

## 截止时间与当前状态

官方表单写明申请采用 **rolling basis（滚动审核）**，截至核验日期没有公布固定截止日。官方条款允许 OpenAI 随时修改、暂停、限制或终止计划，所以提交前应再次打开官方表单确认状态。

## 官方表单字段

### 必填

1. 姓氏
2. 名字
3. 电子邮箱（必须与 ChatGPT 账户关联）
4. GitHub 用户名（个人资料需公开）
5. GitHub 代码仓库 URL（仓库需公开）
6. 维护者角色：主要维护者或核心维护者
7. 为什么该仓库符合要求（最多 500 字符；可说明 Stars、月下载量或生态重要性）
8. OpenAI 组织 ID
9. 将如何为项目使用 API 额度（最多 500 字符）

### 选填

- 感兴趣的权益：Codex Security、项目 API 额度（可多选）
- 其他补充说明（最多 500 字符）

## 对 DengTa 申请的直接影响

DengTa 在申请前至少需要满足并可公开验证以下事实：

- 公开且可正常构建的源代码仓库；
- 清晰的开源许可证、README、安装说明、功能说明和贡献说明；
- 不包含生产服务器凭据、API 密钥、Supabase 服务密钥、用户聊天记录、个人记忆、备份 ZIP、APK 签名材料或其他私人数据；
- 能如实说明当前维护活动、真实使用情况和生态价值；
- 能提出具体、可信的 API 额度用途，例如 PR 审查、Issue 分类、发布检查、测试生成或维护自动化。

不能把新建公开仓库、临时 Stars 或尚未实现的功能包装成既有影响力。若当前数据不足，可在申请中如实强调项目的技术特点、活跃开发证据和开源生态价值，但不应虚构下载量、用户数或社区采用情况。
