# DengTa 共看会话、重试与迟到回执审查

本轮前端 2.10.44 / Android 92，后端 0.29.19。前端基线 857e0f101421617bd3fca34ab50b87886d0b5a12；后端基线 ae3f22b720cc5fb027a72b2932a08dd450cbff34。

## 根因与改动

1. 原 App 与 Together 开始/结束只检查 React busy，状态更新前两次点击可以同时进入；异步回执也没有账号、伴侣与操作版本校验。
2. 原直链与网页开始函数允许复用任意一种既有视频会话，换模式/链接后仍可能报告开始成功。客户端没有提供 session_id，超时后再开始可能建立另一个会话。
3. 原结束成功会无条件清空播放器与缓存；旧面板卸载后返回的结果可能擦除新面板的恢复记录。没有收到明确结束回执也缺少专门诊断。
4. 原网页编辑后仍允许开始已解析的旧网页；后台刷新、播放进度返回的旧会话可能覆盖新会话或已结束状态。
5. 后端 startCoWatchSession 在检查聊天会话、新视频 URL、歌单归属与媒体加密之前结束既有活动会话，无效替换也会停掉当前共看。

文件与行为：

- `src/co-watch-lifecycle.js:5`：同步锁贯穿建立/结束，操作捕获账号/伴侣和版本；失效取消 AbortController，旧 finally 不会解锁新操作。每个失败建立意图沿用 UUID，读回相同 ID 的会话可以确认恢复；正常重复开始复用同一次已确认请求。不同链接/模式或另一设备的 ID 明确返回 co_watch_active_conflict，不伪装为当前视频已开始。结束必须收到相同 ID、ended 状态；失败保留本地会话。
- `src/co-watch-request-scope.js:1`：复用现有 authSession，每次取凭据前后核对账号与伴侣，在凭据刷新期间切换范围也不能把请求发送给新伴侣。迟到响应不能向新范围写伴侣选择或使新账号登录失效。没有改变认证、凭据刷新、权限和私网防护。
- `src/co-watch.js:122`、`:133`、`:157`、`:174`、`:239`：活动会话读取、创建、结束、进度与聊天读取可传取消信号和固定范围，创建序列化 session_id。旧调用可不传可选参数，冻结的 src/api.js 未修改。
- `src/App.jsx:1221`、`:1281`、`:1669`、`:6055`、`:6230`、`:6295`：网页/直链开始和结束统一进入控制器，切换账号/伴侣使旧操作失效，提交立即更新会话 ref。后台读取与进度回执检查范围、版本及会话 ID；旧结果不能恢复已结束会话或覆写新会话。
- `src/Together.jsx:131`、`:355`、`:396`、`:414`、`:425`、`:476`、`:489`：面板同步防连点，等待期间禁用开始/结束/载入；开始操作取消尚未结束的旧网页解析。卸载失效本地回执，成功结束只清理对应播放器，编辑过的新草稿不会被旧结果清空。网页地址变更后需重新解析；无回执显示失败，失败结束保留恢复记录。几个固定本地错误码附在反馈中。
- `services/co-watch-sessions.js:399`：活动会话退休步骤移动到新输入校验、归属检查与加密完成之后；无效输入、缺聊天会话或加密故障不结束旧会话。数据库结构与已有读取/更新作用域保持不变。
