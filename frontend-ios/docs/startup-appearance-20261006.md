# DengTa 2.10.65 启动、外观与一起看流程修复

本轮基线：前端 `f1e85b3e2227c04b30a8c84179ec53a55fa1ff52`，后端 `8dd525b2d15cada57cacf80d293e9c9cabcf2ad9`。目标是修复已经复现的操作故障，延续现有设置分类、长文本编辑器和陪伴灵感签。生产发布与实际验证结果记录在 `E:/chatgpt/artifacts/dengta-startup-20261006/report.md`，不能仅凭此源码报告宣称上线或端到端通过。

## 已复现问题与行为变化

| 问题 | 根因与最小修复 |
| --- | --- |
| 切账号/伴侣后突然回到旧伴侣，或新会话被旧 401 注销 | 启动 bootstrap、模型目录、语音状态和预热使用默认认证管理器；页面的 await 后检查晚于 API 层捕获伴侣头和会话失效处理。请求现在固定发起时的账号/伴侣并携带生命周期取消信号；取消后不捕获头、不影响新的登录状态。 |
| 停止重连后仍显示连接成功 | 重连控制器成功分支缺少停止判断，现在忽略停止后的迟到结果。 |
| 外观选择被旧读取回退；旧外观保存进入另一个账号 | 外观 GET 缺少编辑版本检查，260ms 定时器和串行保存未在卸载时取消。现在检查编辑版本，取消计时器，并在实际发送、返回和写本地存储前校验作用域。 |
| 一起看切到直链/网页后会话消失 | 默认轮询仍查询初始屏幕模式。现在分别保留视频与听歌入口的选中模式，离开页面或切模式后丢弃旧读取。自动轮询与人工刷新各自排序；慢轮询在途时不重复发送同模式查询。 |
| 服务器返回了弹幕，页面不显示 | 前端共看回复适配器丢弃 `danmaku`，现在透传数组，保留服务器文字和时间位置。 |
| 保存接口时连击重复创建，或回包清空新草稿 | 同步操作锁阻止重复提交；保存发起时快照只清除仍与提交内容相同的草稿；旧目录探测不覆盖新网关选项，编辑中的已有接口字段在刷新后保留。 |
| 接口已保存，但列表读取失败被解释成保存失败/等待迁移 | 区分保存成功、结果未确认和列表刷新失败；提供只读取状态/列表的“刷新接口列表”，避免自动重复写入；错误反馈保留稳定错误码和 HTTP 元数据，不展示未经映射的上游错误正文。 |

## 修改位置

- `src/App.jsx`：共看入口与慢轮询作用域；外观保存定时器和读取版本；启动、模型目录、语音状态和预热的作用域请求；卸载清理。
- `src/co-watch-view-scope.js`：视频/听歌模式、页面及账号/伴侣变化、人工/自动读取顺序的轻量状态。
- `src/co-watch.js`：共看回复弹幕回执透传。
- `src/startup-reconnect.js`：停止后的成功结果守卫。
- `src/voice-output.js`：状态读取与 404 回退透传请求选项；其他语音写接口未改变。
- `src/AiProviderCenter.jsx`：操作锁、读取版本、草稿保护、作用域取消和部分成功反馈。
- `test/startup-scope-lifecycle.test.js`、`test/startup-service-scope.test.js`、`test/chat-skin-scope-lifecycle.test.js`、`test/co-watch-adapter.test.js`、`test/co-watch-view-scope.test.js`、`test/ai-provider-lifecycle.test.js`：使用实际源函数/组件与真实 API、认证管理器，配合虚构 SDK、fetch 回执和内存存储复现上述故障。
- `test/settings-save-lifecycle.test.js`、`test/chat-latency.test.js`：适配启动请求选项的测试夹具；原断言目标保留。
- 包版本、Android 版本及发布版本断言更新至 `2.10.65 / 113`，没有依赖升级。

修复前日志、修复后定向测试、完整前后端检查、APK 资源/签名/版本检查和生产资源核对分别保存到上述 artifacts 目录。最终报告列出准确行号、实际命令和退出码、GitHub/CNB 状态、APK 哈希与浏览器截图。

虚构回执测试不能替代生产多账号、供应商、Supabase 管理面和真机验收。没有可用 ADB 设备时不得宣称真机安装、帧率或全功能端到端成功。取消只能阻止未发起操作及迟到客户端副作用，已到达服务器的写入必须刷新核对；没有为接口创建新增后端幂等协议。未完成整个 App 所有网络入口的作用域审查，也没有将输入容量等同于无限模型上下文。

可延续的下一步产品思路：在已存在的播放回执和账号/伴侣范围上做“继续上次一起听/看”的入口；将草稿、等待确认、已保存和只需刷新解释成统一的操作状态，减少用户重复点击。它们目前是建议，不计入本轮已实现功能。
