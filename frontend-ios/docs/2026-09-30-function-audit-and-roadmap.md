# 灯塔全功能审查与下一步产品方案

本轮前端 2.10.35 / Android 83，后端 0.29.11。审查基线：前端 f930bf5、后端 69ae70b。开始时两个工作树均干净。

这是一轮按功能入口、接口、测试和故障恢复进行的审查，不是“所有真实场景均通过”的声明。真实账号的模型调用、第三方扫码、外部 MCP、推送送达、多人观影和 Android 真机仍需各自验收。

## 已确认并修复的缺陷

1. 工作区 IndexedDB 使用全局 path 主键，没有账号归属；切换账号后同名文件可能读到其他账号的缓存。新 account-files 存储使用 account + path 复合主键，列表、删除、清理都限定当前账号。旧的无归属缓存保留，但不读取、不自动归给任何账号，避免错迁移。云端文件不变。
2. 缓存读取和列表返回 IDBRequest 而不是 request.result；离线正文与缓存数量实际不可用。现在等待事务完成后返回请求结果，缓存空文件也有效。
3. 云端目录读取失败时整个列表消失，即使已有缓存也无从打开。现在按本账号缓存重建文件夹列表，明确显示离线副本；只读查看与下载可用，恢复连接后刷新。
4. 新的文件读取可能被旧请求的晚到响应覆盖。加入请求序号和卸载失效处理，禁用加载期间编辑；账号/伴侣切换重新挂载页面。
5. 文件列表首次下载使用旧编辑器闭包，可能无输出或导出上一份内容。下载改用本次读取返回的文件名和正文，真实浏览器下载已验证。
6. Storage 的文件夹是 id/metadata 为 null 的条目，不一定以斜杠结尾。现在正确区分目录与 application/octet-stream 文件，空文件也计数。
7. 工作区统计漏掉子目录、没有分页、吞掉存储错误。现在递归与分页遍历，最多 500 条、深度 2；达到边界明确标为部分统计，失败进入既有错误链路。
8. 文本截取错误地用 UTF-8 字节数判断字符超限。改为按解码后文本长度判断；超过 200,000 个 JavaScript 字符单位的预览只读，不缓存成完整文件，追加也禁止用截断材料覆盖原文件。工作区导入先检查 5MiB 存储容量，避免先在手机上全量读大文件。
9. 工作区编辑器按钮在窄屏被卡片裁切。新增局部布局规则，让标题、路径与操作自然换行；360/390 像素按钮边界测试通过。
10. 服务面板把读取设置称为“读写链路可用”，把模型目录检查失败也显示正常，把 MCP 地址配置等同连接成功。现在区分设置读取、未测试、目录失败、接口过期及真实生成待验证；外部记忆未配置时引导用户自助连接。
11. 玩法搜索只匹配标题，搜索“电影、桌宠、MCP、新手、离线文件”难以发现已有入口。新增解释性副标题和别名搜索，支持大小写、全角与多个关键词；保留原有 13 个入口和导航顺序。
12. 7 个已有测试文件未进入 npm test 可达链路。补齐扫码登录、设备摘要、音乐理解、网页嵌入、视觉描述与 Android 播放生命周期测试入口。网易云测试仍断言已废弃的 unknown 设备号，已改为检查当前二维码参数、设备号格式及 HTTPS 登录链接与二维码的一致性，没有为此改供应商请求实现。

## 优先值得做的新功能（尚未实现）

不再新增一排主导航，优先把功能嵌入已有聊天、记忆、小棉花和成就页面。以下是产品设计提案，不是已上线功能。

| 优先级 | 新能力 | 具体使用方式 | 落地边界 |
| --- | --- | --- | --- |
| P1 | 共同故事存档 | “一起玩”的故事可起名、标章节、选择上次停住的位置；下次一键把选中的片段放进输入框 | 用户确认后发送；不自动改写世界书或人格；先做记录与选择，避免多一次模型请求 |
| P1 | 我们的纪念册 | 把用户选中的聊天、票根、日记和小棉花截图放成一张可编辑的小卡 | 私密默认、本地/账号内保存；分享前预览；不是自动公开全部聊天 |
| P1 | 记忆来源卡 | 查看“这段记忆来自哪次聊天、哪个外部库、什么时候”；矛盾时并排让用户选择 | 只显示来源回执，不展示隐藏推理；修改记忆要逐项确认 |
| P1 | 轻量陪伴小计划 | 一次选择一件 2 分钟小事，完成后留下自己的纪念；随时暂停和跳过 | 无惩罚、连续签到和强制弹窗；复用现有成就系统 |
| P2 | 聊天接续卡 | 回来时可打开“上次停在这里”，定位最后一次正常回复、故事章节或播放记录 | 读取记录，用户决定是否发送；不把错误提示和拒答当记忆 |
| P2 | 语音接力 | 正文按句产生可播放队列，支持打断、停止后释放旧音频、各轮音频隔离 | 必须先验证供应商流式能力和授权；以首声延迟、播放间隙实测，不承诺零缓存或固定毫秒 |
| P2 | 小棉花的主题小屋 | 同一个原模型在阅读、观影、纸箱飞船主题中少量互动，装饰跟纪念卡联动 | 增加副本内的资源与场景；原工程保持不变；默认限制并暂停非必要动画 |
| P2 | 连接体检向导 | 在一个页面逐步检查后端、配置、模型目录、可选虚构短句生成、MCP 工具目录 | 每步独立结果；真实付费测试明确由用户点击；不批量自动调用全部接口 |

建议顺序：先处理待授权的数据权限问题与功能失败恢复，再做故事存档和纪念册，随后测长历史与低延迟语音。既有“灵感盲盒、三个词接龙、二十问、新手引导、可编辑记忆”已经存在，不把它们包装成新功能。

## 不变项与限制

- 主聊天和其他生成模块的提示词装配、模板、用户提示词、记忆、世界书、档案原文未改；没有新增主题关键词过滤、拒答或供应商绕过逻辑。
- inventory.json 记录冻结文件 SHA-256，并与 Git HEAD 比对规范化行尾后的内容及空 diff。Windows CRLF 与 Git LF 的原始字节哈希不一定相同，不能把这个差异误报成修改。
- 本轮没有生产数据库迁移、用户文件写入、历史数据清理、密钥轮换或真实下单。
- 上一任务发现的 8 张表 RLS 问题仍待单独授权，本轮未偷偷修改权限。
- 前端检查名为 typecheck，但项目没有 TypeScript；实际执行 ESLint。后端是 151 个运行文件的 node --check，不能称为 TypeScript 类型证明。
- 新缓存保留旧 store，不改变云端内容。回退到旧 APK 可能不能打开版本 2 的 IndexedDB；离线缓存可从云端重新建立，禁止为回退先卸载丢失本机数据。
