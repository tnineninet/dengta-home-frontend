# 外卖小助手：聊天内弹窗与自动点餐链路（2026-10-19）

本文记录 DengTa 外卖功能当前的端到端设计、与参考实现 `sanqianzilanyue/ai-order-takeout` 的对应关系，以及仍然存在的边界。它描述的是**代码中的真实行为**，不代表真机或生产已验收。

## 1. 用户在聊天里怎么用

1. 在聊天输入框直接说「帮我点个外卖，想喝冰美式」。
2. 命中点餐意图时，聊天页会浮出「今天吃什么」任务面板（Kimi 式底部面板），并把这句话自动填进需求框。
3. 也可以从侧栏「🛵 外卖」或聊天里的任务卡打开同一个面板。
4. 点「让 AI 帮我挑」后，面板收起也不影响任务；聊天里会留一张进度卡，随时可以点回来。

面板只负责表达需求、展示进度和最后核对；真正的页面操作在 Android 原生外卖窗口里完成，付款永远由用户本人确认。

## 1.1 第一次使用（Android）

1. 打开侧栏「🛵 外卖」→ 展开「平台登录与连接」→「扫码登录外卖」，用饿了么 / 淘宝闪购账号登录一次。
2. 回到聊天，直接说「帮我点个外卖，预算 30，想喝冰美式」。
3. 面板浮出后点「让 AI 帮我挑」，可以收起面板继续聊天；进度会留在聊天里的任务卡上。
4. AI 找店、读菜单、加购并核对金额；到「等你核对付款」时点「回到平台页面付款」，自己确认地址并付款。
5. 遇到验证码、登录失效或金额对不上，它会停下来把页面留给你，不会重复加购。

## 2. 端到端链路

```
聊天输入 ──意图命中──▶ TakeoutAssistant（任务面板）
      │                        │ buildTakeoutRequest()
      ▼                        ▼
sendMessage() ──▶ 模型 tool_call(takeout_order) ──▶ takeout-tool.js
                                                      │ createCommand / waitForResult
                                                      ▼
                                             takeout-channel.js（持久命令 + 幂等）
                                                      │ pending / ack / progress / result
                                                      ▼
                              takeout-executor.js（轮询 + 崩溃标记 + 暂停/恢复）
                                                      │ OrderBrowser 插件
                                                      ▼
                       OrderWebActivity（真实 WebView，真触摸点击，停在付款前）
                                                      │ 回执 JSON
                                                      ▼
                    面板展示店铺 / 菜单 / 选中商品 / 合计 → 用户回到页面付款
```

关键约束：

- **一次聊天最多三步**：search → menu → order，每个动作各一条命令；只有「换店 / 换菜」这类没有改动购物车的失败才允许有界重试（最多 5 次工具执行 / 6 轮模型请求）。
- **预算、备注、份数跨步骤继承**：第一次说过的预算会带进后续 order；后续不能放宽预算，也不能中途改份数。
- **付款前停手**：`ready_for_payment` 必须同时满足：状态正确、金额是正数、明细只有一项且商品名一致、份数一致、`paymentSubmitted=false`、回执已同步。任一不满足都转为人工核对。
- **绝不自作主张**：没有读到真实菜单就不下单；找不到精确商品不替换；验证码、登录失效、超时、金额不明都交回给人。

## 3. 面板行为（Kimi 式）

- 空闲：需求输入 + 灵感 + 预算/人数/忌口 + 「AI 会怎么做」四步说明。
- 进行中：助手气泡、四步时间轴、当前店铺/商品、候选店铺（评分）、真实菜单（价格、售罄、AI 选中）、暂停按钮。
- 待付款：合计、商品行、`回到平台页面付款`，以及「DengTa 不会替你付款」的说明。
- 失败：保留错误码与可恢复提示，不把失败说成完成；可重试的失败继续显示为「正在换一家」。
- 无任务时收起面板不会丢草稿；账号或伴侣切换后，旧任务的菜单和金额不会显示在新作用域。

## 4. 原生侧稳定性改造

| 用户反馈 | 处理 |
| --- | --- |
| 掉登录 | 页面 `onPause/onStop`、返回灯塔、登录页退出时同步 `CookieManager.flush()`；登录页与点餐页共用同一账号 WebView Profile；登录页被系统回收时自动重开同一页 |
| 闪退 | WebView 渲染进程被回收时自动重建同一 URL（最多 2 次），并把本轮如实标记为「页面中断」而不是直接判死 |
| 网页自己关闭 | 禁止 `window.open` 多窗口、吞掉 `window.close()`、非用户手势的 `taobao://` 等外部跳转一律拦截；返回键第一次只提示不关闭 |
| 刷新/跳走 | 下一步还是同一 URL 时不再销毁重建 WebView，只继续当前步骤；只有确实换页时才重载 |
| 屏幕熄灭导致卡住 | 自动点餐期间保持屏幕常亮 |
| 回不到付款页 | 新增 `resumePage`：面板上的「回到平台页面付款」只把已有窗口调回前台，不重载、不点击、不提交 |
| 网络抖动 | 主文档加载失败自动重试一次，再失败才显示可恢复的技术错误页 |

## 5. 从参考实现学到的、已经落地的规则

参考文章《让 AI 替你点外卖》记录了 47 个真实坑（h5.ele.me / 淘宝闪购 H5）。DengTa 采用 WebView 而非 CDP，但页面层的规则同样适用：

- 店卡以「分」评分作为身份证，免起送的店不能被过滤掉。
- 点击用真实触摸坐标，落点前用 `elementFromPoint` 验身，被浮层压住就换九宫格落点。
- 找按钮按位置（底部通栏）而不是精确文案；`合计` 存在「合计¥」和「合计/已优惠/实付」两种写法。
- 商品卡只认标题类名；排除「买过 / 再来一单」面板，避免整张旧单倒进购物车。
- 规格默认已选就不要乱点；加购是两段（详情页 → sku 面板 → 通栏按钮）。
- 验证码要三路识别（正文 / DOM / 可见壳），撞上就停手交给人。
- 结算金额是「钱的闸」：超过预算或车里有旧货就停，绝不提交。

## 6. 仍未验证 / 已知边界

- 没有真机、真实淘宝闪购账号、真实支付；平台 DOM 改版、Cookie 有效期、厂商后台冻结仍需实机验收。
- 原生自动操作目前只可靠支持单份商品；多份、复杂规格、备注会明确转人工核对。
- 重试上限固定为 5 次工具执行，超限后必须由用户重新发起，不会无限循环。
- 「记住这家店/这个口味」尚未实现；每次需求都从当轮真实搜索结果开始。
- 只有 OpenAI Chat / 自定义兼容路径完整支持原生点餐工具循环；Anthropic、Gemini、Responses 仍受各自工具循环能力限制。
