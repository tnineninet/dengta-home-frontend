# 待确认导入的明确恢复操作

导入提交超时后，GET 返回 `preview` 只能说明尚未看到完成标记，不能证明原提交没有写入。若原 POST 根本未到达服务器，旧版面板会一直等待，无法继续导入。

现在先点击“检查提交结果”，仍为 `import_commit_pending` 时，可明确选择“放弃旧候选并核对结果”。该操作只发送旧导入 ID 和 `confirm_reject_pending: true`，不会发送新候选、重新创建预览或直接删除已有记忆。

后端复用已有的账号与伴侣作用域及原子提交事务，将尚未提交的全部旧候选标记为拒绝。若原提交先完成，则返回原结果，保留已保存内容。放弃先完成后，迟到且决策不同的原提交会得到冲突错误，不能继续写入。

前端仅在协议、任务 ID、完成状态和候选计数都匹配后解锁。网络异常或不完整回执继续保留编号；大文件放弃本段时回到该段起始字节，重新选择原文件，不跳过未导入部分。关闭重开和核对 GET 不会自动执行放弃或提交。

没有数据库迁移，没有提示词装配变化，没有真实用户内容清理。API/React、租户隔离、本地 PostgreSQL 事务测试和手机宽度虚构页面操作已通过；PGlite 注入两种到达顺序不等于生产多连接并发实测。真实账号和 Android 真机仍待验收。
