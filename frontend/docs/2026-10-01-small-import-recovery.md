# 小文件与粘贴导入的提交回执恢复

适用版本：前端 2.10.59 / Android 107。后端沿用 0.29.26 的原子导入协议，无数据库迁移。

原问题：分段大文件有字节检查点，小文件和粘贴导入的未知提交结果却只在面板状态中保存。提交超时或关闭面板后，重新打开可能再次预览并追加同样内容。

现在在发出提交请求前，保存所属账号、伴侣和导入编号的技术收据。每个编号独立保存，只含版本、编号、内容类型和开始时间；不保存文件名、正文、用户决策或凭据。重开面板会展示待核对卡片，读取服务器结果，不自动再次提交。服务器仍是预览状态时不能断言事务已回滚，因此保持待核对；只有匹配的已完成回执或已知零写入错误才解除本次保护。

服务器找不到旧预览时显示 import_receipt_missing 和 HTTP 状态，用户先核对已保存内容，再明确选择重新预览。此操作只移除本地技术收据，不删除服务器上的记忆、世界书或个性化字段。多个待核对编号分别检查，核对一个不会移除其他编号。

账号、伴侣的存储键分段编码；现有 App 按账号和伴侣为面板设置 key。旧面板的迟到响应不能刷新新伴侣。存储不可用时同一页面的内存收据仍保护关闭重开，并提示不要刷新或退出；浏览器清空存储、换设备或完整进程退出无法保证恢复。没有保存未提交的候选编辑。

新增测试覆盖原文不进入收据、账号与伴侣隔离、多个编号、坏记录、跨标签删除、存储被禁、小文件与粘贴超时后关闭重开、预览状态继续锁定、GET 确认不重复 POST、404 手动复核，以及提交中关闭保留编号。现有大文件指纹、字节进度和原子导入回归保留。

本地虚构浏览器验收：390px 待核对卡片和 360px 核对成功均无横向溢出、无 console error；核对前后只发生一次写入。截图和完整命令退出码位于 E:/chatgpt/artifacts/dengta-small-import-recovery-20261001。最终发布、生产构建哈希及 APK 签名以该目录 final-state.json / final-audit.md 为准。

没有修改提示词装配、用户个性化原文、长期记忆内容、供应商输出处理或账号权限。附件容量与模型上下文没有改变。实际账号、供应商和 Android 真机验收尚未执行，不能据此宣称所有模块端到端通过。
